# قاعدة البيانات المحلية

تستخدم النسخة الأولى SQLite عبر حزمة sqflite، حتى تعمل بيانات الطالب والمحتوى والتقدم دون اتصال بالإنترنت.

## قواعد التصميم

- قاعدة البيانات محلية على الجهاز ولا تتطلب حساباً أو خادماً.
- لا تُدرج أسماء مسارات أو مواد دراسية قبل التحقق من المنهج السوداني الرسمي للصف المعني.
- يمكن ربط المادة بالصف مباشرة أو بمسار محدد.
- تُميز حقول `source_label` المحتوى الرسمي عن المحتوى الإضافي.
- تحفظ الكتب والوسائط الكبيرة كملفات محلية، بينما تحفظ قاعدة البيانات بياناتها الوصفية ومساراتها.
- تستخدم المفاتيح الخارجية لمنع السجلات اليتيمة.

## الجداول الحالية

| المجموعة | الجداول |
|---|---|
| الهيكل الأكاديمي | grades, study_tracks, subjects, curriculum_units, lessons |
| التقييم | exams, questions, exam_questions, exam_attempts, attempt_answers |
| تجربة الطالب | student_profiles, bookmarks, study_progress |
| إدارة المحتوى | content_packages |

## الصفوف الأولية

تُنشأ ثلاثة سجلات عامة للصفوف الأول والثاني والثالث الثانوي. هذه سجلات تعريفية للصفوف فقط، وليست ادعاءً باعتماد مسارات أو مواد بعينها.

## الترحيلات

رقم مخطط قاعدة البيانات الحالي 2.

## إصدارات المناهج (Schema v2)

أضاف الترحيل الثاني طبقة مستقلة لتعريف إصدار المنهج وربط المواد به دون إدخال أي مقررات تلقائياً:

- `curriculum_releases`: الصف، المسار الاختياري، السنة الدراسية، رمز/اسم الإصدار، الجهة المصدرة، بيانات المصدر، تاريخ النشر، وحالة التحقق.
- `curriculum_release_subjects`: المواد المرتبطة بالإصدار، ونوع المتطلب (إلزامي/اختياري/غير مصنف)، ومجموعة الاختيار، والترتيب، وحالة التحقق، ومرجع المصدر.
- `curriculum_units.release_subject_id`: ربط اختياري للوحدة بالمادة ضمن إصدار منهجي محدد. يبقى فارغاً للسجلات القديمة إلى حين مراجعتها وربطها يدوياً.

تستخدم حالات التحقق `pending` و`verified` و`rejected`. ولا توجد أي إصدارات أو مواد منهجية مُدخلة تلقائياً في هذا الترحيل. تفرض قاعدة البيانات كذلك توافق صف المادة ومسارها مع إصدار المنهج عبر مشغلات SQLite.

الترحيل متوافق مع قواعد الإصدار 1: يضيف الجداول والعلاقة الاختيارية فقط، ولا يحذف أو يعيد كتابة سجلات الطالب أو المواد أو الوحدات أو الدروس أو الامتحانات. وتُنشأ الجداول نفسها عند تثبيت جديد على الإصدار 2.

يجب أن تظل أي تغييرات مستقبلية متدرجة داخل `_upgradeSchema`، مع المحافظة على بيانات الطالب وتقدمه.

## طبقة الوصول للمناهج

توجد طبقة الوصول في `lib/features/curriculum/data/curriculum_repository.dart`، وتوفر:

- إنشاء إصدارات مناهج بحالة تحقق ابتدائية `pending` افتراضياً، دون إنشاء بيانات منهجية مسبقة.
- استعراض الإصدارات لأعمال الإدارة والتحرير، مع فلاتر الصف والمسار والسنة والحالة.
- استعلاماً مخصصاً للطالب لا يعيد إلا الإصدارات المعتمدة `verified`.
- ربط مادة بإصدار مع تحديد إلزاميتها أو اختياريتها ومجموعة الاختيار ومرجع المصدر.
- استعلاماً للمواد المنشورة لا يعيد المادة إلا إذا كان كل من الإصدار وربط المادة معتمداً، وكانت المادة نشطة ومتوافقة مع الصف والمسار.
- ربط وحدات المنهج بالمادة ضمن إصدار محدد بعد التحقق من تطابق المادة والصف والمسار.

تظل مشغلات SQLite هي خط الدفاع النهائي عند إضافة مادة إلى إصدار، حتى لو استُدعيت قاعدة البيانات من خارج المستودع. ويجب أن تُنفذ مراجعة المحتوى ومراجعة المصدر قبل تحويل حالة التحقق إلى `verified`. لا يعني وجود سجل في قاعدة البيانات أنه صالح للعرض على الطالب.
