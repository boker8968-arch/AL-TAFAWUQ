# خارطة تنفيذ منصة التفوق

## المرحلة 0 — تأسيس المشروع
- [x] إنشاء مستودع مستقل.
- [x] توثيق الرؤية والنطاق والقيود.
- [x] إضافة هيكل Flutter أولي وهوية الألوان.
- [x] إضافة اختبار واجهة أولي وإعداد CI.
- [ ] التحقق الفعلي من التحليل والاختبارات والبناء على بيئة Flutter (لم تُنفذ بعد).

## المرحلة 1 — التحقق الأكاديمي وتجهيز المحتوى
- [ ] حصر الصفوف والمسارات والمواد وفق المنهج السوداني الرسمي الحالي.
- [ ] تحديد مصادر الكتب والمقررات وحقوق الاستخدام.
- [ ] وضع نموذج موحد للكتاب والوحدة والدرس والملخص والسؤال والامتحان.
- [ ] إعداد قائمة المحتوى حسب الصف والمسار والمادة.

## المرحلة 2 — أساس التطبيق
- [x] إعداد اختيار الصف والمسار وحفظ تفضيلات الطالب محلياً (المسارات تبقى غير معبأة حتى التحقق الرسمي).
- [ ] تنفيذ التنقل الأساسي وحالات التحميل والفراغ والخطأ.
- [x] تأسيس قاعدة SQLite المحلية وجداول المنهج والطالب والامتحانات والتقدم.
- [ ] إضافة اختبارات تكامل فعلية لقاعدة البيانات والترحيلات.
- [ ] إعداد البحث والمفضلة.

## المرحلة 3 — تجربة التعلم
- [ ] مكتبة الكتب والمناهج.
- [ ] قارئ الدروس والملخصات.
- [ ] تشغيل الوسائط المحلية.
- [ ] الامتحانات وبنك الأسئلة والتصحيح.
- [ ] حفظ النتائج والتقدم والجدول الدراسي.

## المرحلة 4 — إدارة المحتوى والعمل دون اتصال
- [ ] تصميم صيغة حزم المحتوى وإصدارها.
- [ ] استيراد الحزم والتحقق من سلامتها.
- [ ] النسخ الاحتياطي والاستعادة.
- [ ] اختبار سيناريوهات انقطاع الكهرباء/التطبيق أو نقص مساحة التخزين أثناء الاستيراد.

## المرحلة 5 — الجودة والإصدار
- [ ] اختبارات الوحدات والواجهات والتكامل.
- [ ] مراجعة الأداء واستهلاك التخزين.
- [ ] اختبار أجهزة Android متعددة وأحجام شاشات مختلفة.
- [ ] بناء APK والتحقق من تثبيته وتشغيله.
- [ ] تجهيز وصف التطبيق وسياسة الخصوصية ومواد الإصدار.

## قواعد الاعتماد
- لا يُعلن أي اختبار أو بناء ناجحاً دون نتيجة تنفيذ فعلية.
- لا تُضاف خدمة مدفوعة دون موافقة صريحة.
- لا تُعرض معلومات منهجية غير متحققة على أنها رسمية.
- لا يعتمد التطبيق على الإنترنت لتشغيل وظائف الدراسة الأساسية.
