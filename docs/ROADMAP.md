## المرحلة 2 — أساس التطبيق
- [x] إعداد اختيار الصف والمسار وحفظ تفضيلات الطالب محلياً (المسارات تبقى غير معبأة حتى التحقق الرسمي).
- [ ] تنفيذ التنقل الأساسي وحالات التحميل والفراغ والخطأ.
- [x] تأسيس قاعدة SQLite المحلية وجداول المنهج والطالب والامتحانات والتقدم.
- [x] إضافة ترحيل Schema v2 لإصدارات المناهج وربط المواد بالإصدارات دون إدخال مقررات غير متحققة.

- [x] إنشاء CurriculumRepository لإدارة الإصدارات وربط المواد وفصل بيانات الإدارة عن المحتوى المنشور للطالب.
- [x] إضافة Schema v3 لربط الوحدات بالحزم ورموز المحتوى الثابتة.
- [ ] إضافة اختبارات تكامل فعلية لقاعدة البيانات والترحيلات ومستودع المناهج.
- [ ] إعداد البحث والمفضلة.

## المرحلة 4 — إدارة المحتوى والعمل دون اتصال
- [x] تصميم صيغة حزم المحتوى v1 وإضافة محلل manifest مع التحقق البنيوي من المسارات والملفات والبصمات (الاختبارات لم تُشغّل).
- [x] تنفيذ مستورد محلي يتحقق من مطابقة منهج معتمد ووجود الملفات وأحجامها وSHA-256، ويستورد الوحدات والدروس بمعاملة SQLite مع تنظيف الملفات عند فشلها.
- [x] إضافة اختبارات تكامل للمستورد: الاستيراد الناجح، SHA-256 غير المطابق، غياب اعتماد المادة، منع تكرار الحزمة، والتراجع عند فشل المعاملة (أُضيفت ولم تُشغّل بعد).
- [ ] إضافة واجهة اختيار المجلد وإدارة الاستيراد على Android.
- [ ] دعم تحديث/استبدال وحذف الحزم بطريقة آمنة.
- [ ] اختبار الاستيراد على أجهزة Android وسيناريوهات انقطاع الكهرباء أو نقص مساحة التخزين.
- [ ] النسخ الاحتياطي والاستعادة.

## قواعد الاعتماد
- لا يُعلن أي اختبار أو بناء ناجحاً دون نتيجة تنفيذ فعلية.
- لا تُضاف خدمة مدفوعة دون موافقة صريحة.
- لا تُعرض معلومات منهجية غير متحققة على أنها رسمية.
- لا يعتمد التطبيق على الإنترنت لتشغيل وظائف الدراسة الأساسية.
