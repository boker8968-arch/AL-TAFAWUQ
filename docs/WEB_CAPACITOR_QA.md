# خطة اختبار منصة التفوق — Web / Capacitor

يبدأ اختبار الشاشات الكامل بعد اكتمال الوظائف الأساسية، وفق طلب صاحب المشروع. فحوص CI البرمجية وبناء APK تستمر أثناء التطوير ولا تُعد بديلاً عن اختبار الواجهات الفعلي.

## 1. فحوص آلية قبل اختبار الواجهات

- [ ] `node --check` لجميع وحدات JavaScript.
- [ ] `npm test` لاختبارات manifest والتحقق من الحزم وعزل بيانات مفاتيح الإجابة.
- [ ] `npm run build` وإنشاء مجلد `www` شاملاً PDF.js والموارد المحلية.
- [ ] `npx cap sync android` دون أخطاء.
- [ ] `./gradlew assembleDebug` وإنتاج APK.
- [ ] التحقق من أن ملف APK الناتج يطابق أحدث commit في فرع `web-capacitor-migration`.

## 2. اختبارات شاشات الطالب

- [ ] الرئيسية: الهوية البصرية، وضوح الأقسام، عدم تداخل شريط التنقل السفلي مع المحتوى.
- [ ] ملف الطالب: حفظ الاسم والصف والمسار، ثم إغلاق التطبيق وإعادة فتحه والتحقق من بقاء البيانات.
- [ ] تغيير الصف أو المسار: التأكد من عدم عرض محتوى صف أو مسار آخر.
- [ ] المناهج: لا تظهر إلا الوحدات التابعة لحزم معتمدة وإصدارات وربط مواد موثقة.
- [ ] الدروس: الملخص، النص العربي، اتجاه RTL، وحفظ التقدم.
- [ ] قارئ PDF: فتح ملف محلي، التنقل السابق/التالي، صفحات متعددة، العربية والخطوط، وإغلاق القارئ دون تسرب واجهة أو ذاكرة.
- [ ] المذكرات: تصنيفها تحت «المذكرات»، وفتح ملفات PDF والنصوص محلياً.
- [ ] الامتحانات: بدء محاولة، اختيار الإجابات، حفظها، استئنافها، العد التنازلي، التسليم اليدوي والتلقائي، وسجل المحاولات.
- [ ] لوحة التقدم: عدد الدروس المكتملة، النسبة، وقت الدراسة، والمحاولات المكتملة.

## 3. اختبارات عدم الاتصال

- [ ] تشغيل التطبيق بعد تثبيته مع إيقاف الإنترنت.
- [ ] فتح الواجهة الرئيسية والتنقل بين الشاشات دون اتصال.
- [ ] فتح ملف PDF بعد تنزيل/تثبيت موارد PDF.js المحلية.
- [ ] التحقق من أن أي طلب لمحتوى غير موجود لا يعرض بيانات تجريبية أو محتوى غير معتمد.
- [ ] التحقق من بقاء بيانات الطالب والتقدم والمحاولات بعد إغلاق التطبيق وإعادة تشغيل الهاتف.

## 4. المقاسات والتوافق

اختبار العرض على عروض تقريبية: 320، 360، 375، 390، 412، و600 بكسل، مع فحص:
- عدم وجود تمرير أفقي غير مقصود.
- قابلية الضغط على الأزرار وحقول الإدخال.
- وضوح النصوص العربية وعدم قص العناوين.
- احترام مناطق النظام الآمنة في Android.

## 5. تثبيت Android على جهاز فعلي

- [ ] تثبيت APK على Android 14 أو أحدث.
- [ ] فتح التطبيق وإغلاقه وإعادة تشغيله.
- [ ] التأكد من عدم ظهور خطأ تحليل الحزمة.
- [ ] اختبار قارئ PDF والامتحان المؤقت على الهاتف.
- [ ] اختبار تحديث قاعدة IndexedDB من الإصدار 6 إلى 7 دون فقد بيانات الطالب أو التقدم أو المحاولات.
- [ ] تسجيل نوع الجهاز وإصدار Android ونتيجة كل اختبار.

## 6. تقرير التسليم

بعد إتمام الاختبارات، يُكتب تقرير يميز بوضوح بين:
1. اختبارات آلية ناجحة.
2. شاشات تم اختبارها على متصفح.
3. اختبارات تمت على جهاز Android فعلي.
4. عيوب أُصلحت وأعيد اختبارها.
5. نقاط ما زالت تحتاج جهازاً أو بيانات محتوى معتمدة.

لا يُعلن التطبيق جاهزاً للإصدار النهائي قبل إكمال اختبار التثبيت والتشغيل على جهاز Android فعلي ومراجعة أي ملاحظات متبقية.
